# M1 手動測試清單

`docs/execution-plan.md` 5.9 的矩陣，展開成可以逐項打勾的版本。
每一項都寫了「怎麼做」和「應該看到什麼」，看到不一樣的就是問題。

**做法**：把 `- [ ]` 改成 `- [x]` 表示通過，`- [!]` 表示有問題，並在下面補一兩句說明。
全部跑完大約 1～2 小時，可以分次做。

---

## 開始之前

程式在 `build\ci\bin\Release\TranslationMagicWindow.exe`，雙擊執行，圖示會出現在系統匣。

**目前的設定**：翻譯先用本機的 `hy-mt2`（`http://127.0.0.1:11434/v1`），失敗時退回 Google。
測試前先確認 Ollama 有在跑，否則每次翻譯都會等它逾時。

**快捷鍵**

| 快捷鍵 | 做什麼 |
|---|---|
| `Ctrl+Alt+Shift+T` | 立即翻譯（不等畫面穩定） |
| `Ctrl+Alt+Shift+D` | 除錯傾印：把當下的畫面、辨識結果和記錄存成一個資料夾並開啟它 |
| `Ctrl+Alt+Shift+S` | 把透鏡範圍存成 PNG（開發用） |

**系統匣選單**：顯示透鏡／開啟結果視窗／立即翻譯／暫停／設定…／除錯傾印／除錯覆蓋框／
畫面穩定後自動存成 PNG／擷取目前畫面／開啟擷取資料夾／結束。

**透鏡邊框的顏色**

| 顏色 | 意思 |
|---|---|
| 藍 | 顯示中（平常的樣子） |
| 橘 | 正在拖動或縮放 |
| 黃 | 放開了，等畫面穩定 |
| 紫 | 處理中（擷取 → OCR → 翻譯） |
| 綠／紅 | 手動擷取成功／失敗 |

**遇到任何問題時**：先按 `Ctrl+Alt+Shift+D`，它會開啟一個資料夾，裡面有當時的畫面、
辨識到的每一行、譯文、耗時和記錄檔。把那個資料夾給我，比文字描述好查十倍。
**金鑰不會在裡面**，可以放心。

> 想看它「到底讀到什麼」的時候，打開系統匣的「除錯覆蓋框」：
> 透鏡上會直接畫出 OCR 讀到的每一行（細的青色框）和合併後的段落（粗的洋紅色框）。
> 句子被切錯時，一眼就看得出是哪一步錯了。

## 1. 顯示

- [ ] **縮放 100%**：設定 → 系統 → 顯示器 → 縮放改成 100%，重新啟動程式。
      透鏡的邊框和右下角的把手大小正常，擷取到的內容和看到的一致（沒有偏移或縮放）。
- [ ] **縮放 125%**：同上。
- [ ] **縮放 150%**：同上。
- [ ] **縮放 175%**：同上。
- [ ] **兩個螢幕用不同的縮放比例**：把透鏡從一個螢幕拖到另一個。
      透鏡的實際大小跟著改變（維持看起來一樣大），翻譯結果仍然對得上位置。
- [ ] **HDR 開啟**：開啟 HDR 之後翻譯一段文字。顏色可能偏淡，但**文字要讀得出來**。
- [ ] **HDR 關閉**：關掉之後再翻一次，確認沒有殘留問題。
- [ ] **高更新率螢幕**（有 120Hz 以上的話）：把更新率調到最高，拖動透鏡。
      拖動時邊框是橘色、放開後變黃再變藍，不會卡頓或閃爍。

## 2. 內容

每一項都：把透鏡放到有文字的地方 → 放開 → 等它自己翻譯（或按 `Ctrl+Alt+Shift+T`）。

- [ ] **Chrome 的日文網頁**：譯文出現在結果視窗，原文和譯文成對。
- [ ] **Edge 的日文網頁**：同上。
- [ ] **Firefox 的日文網頁**：同上。
- [ ] **本機的漫畫閱讀器**：直排日文的閱讀順序**從右到左**，沒有反過來。
- [ ] **網頁漫畫**：同上。
- [ ] **振り仮名（ルビ）**：找一頁有標音的漫畫。譯文卡片上，讀音要顯示在對應的漢字旁邊。
- [ ] **韓文條漫**：韓文可以辨識並翻譯。
- [ ] **英文內容**：英文網頁或遊戲，翻譯正常。
- [ ] **無邊框視窗模式的遊戲 1**：____________（寫下遊戲名）
- [ ] **無邊框視窗模式的遊戲 2**：____________
- [ ] **無邊框視窗模式的遊戲 3**：____________
      遊戲要點：畫面能擷取到（不是全黑）、遊戲本身不會掉幀、
      **結果視窗不會每隔幾秒跳到遊戲前面**（只有第一次會出現）。

## 3. 操作

- [ ] **拖動**：抓著邊框拖動，透鏡跟著走，放開後自動翻譯。
- [ ] **縮放**：拖右下角的把手改變大小，放開後用新的範圍翻譯。
- [ ] **快速來回移動**：快速拖來拖去再放開。不會當掉，也不會卡在「處理中」（紫色）不出來。
- [ ] **把透鏡拖到結果視窗上**：結果視窗的內容**不會**被擷取進去（不會翻譯自己的譯文）。
- [ ] **在透鏡中間點擊**：點擊穿透到底下的視窗（例如點得到網頁上的連結）。
- [ ] **在透鏡中間捲動**：捲動穿透到底下的視窗，捲完之後會重新翻譯。
- [ ] **拖動到另一個螢幕**：透鏡正常顯示，翻譯的是新螢幕上的內容。

## 4. 環境

- [ ] **睡眠後恢復**：讓電腦睡眠再喚醒。透鏡還在，翻譯功能正常（不需要重開程式）。
- [ ] **拔掉螢幕**：拔掉一個螢幕（或關掉延伸顯示）。程式不會當掉，透鏡回到剩下的螢幕上。
- [ ] **接上螢幕**：接回去之後一切正常。
- [ ] **斷網**：關掉網路。用本機模型時翻譯照樣可用；
      如果引擎退回 Google，卡片上會**說明為什麼失敗**（而不是空白或當掉），原文仍然顯示。
- [ ] **CPU 模式**：用 `TranslationMagicWindow.exe --ocr-device cpu` 啟動（模擬沒有顯示卡的電腦）。
      翻譯仍然可用，只是比較慢。記錄檔第三行應該寫「OCR 裝置：cpu」。
- [ ] **重複啟動**：程式已經在跑時再點一次執行檔。不會開第二個，而是把透鏡顯示出來。

## 5. 結果視窗（MT-UI）

- [ ] **捲動**：翻譯幾次之後往上捲看歷史，畫面**不會**被新卡片拉回底部。
- [ ] **回到最新**：往上捲時出現「回到最新」，按下去回到底部並繼續跟著新卡片。
- [ ] **置頂**：打開置頂，視窗留在其他視窗上面；關掉之後恢復正常。
- [ ] **字級**：加大、縮小，文字跟著變，版面不會亂掉。
- [ ] **深淺色**：把 Windows 切換成深色／淺色模式，結果視窗跟著變。
- [ ] **清除**：按清除之後卡片清空。
- [ ] **重新啟動後還原**：移動並縮放結果視窗 → 結束程式 → 重新啟動。
      位置、大小、字級和置頂設定都還在。

## 6. M1 新增的功能

- [ ] **設定視窗**：系統匣 →「設定…」。切換 Google／LLM，改模型名稱，存檔。
      不必重開程式就生效（下一次翻譯就會用新的引擎）。
- [ ] **金鑰不會被讀出來**：存過金鑰之後重開設定視窗，金鑰欄是空的，
      下面寫「已經設定過金鑰。留空表示不更改」。留空直接存檔，金鑰不會被洗掉。
- [ ] **詳細診斷**：打開之後，記錄檔裡才會出現辨識到的文字和譯文（原本寫的是「（略）」）。
- [ ] **除錯傾印**：按 `Ctrl+Alt+Shift+D`。資料夾會自己開啟，裡面有
      `capture.png`、`report.json` 和 `logs\`。`report.json` 裡**找不到金鑰原文**。
- [ ] **除錯覆蓋框**：系統匣打開「除錯覆蓋框」。透鏡上出現 OCR 的框和左上角的狀態、耗時；
      滑鼠**穿透得過去**（點得到底下的視窗）；而且框**不會**被翻譯進去。再按一次關掉。
- [ ] **暫停**：系統匣 →「暫停」。畫面變了也不再自動翻譯；取消暫停後恢復。
