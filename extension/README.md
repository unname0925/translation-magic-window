# 網頁漫畫擴充功能（Chrome／Edge，原型）

在瀏覽器裡看漫畫時，按一下工具列的按鈕，整章的圖片都會翻成繁體中文、直接蓋在原圖上，
不用停下來等。翻譯由電腦上的 Translation Magic Window 做（OCR、manga-ocr、翻譯引擎、背景修補都沿用），
擴充功能只負責找圖、送圖、把譯文畫回網頁。設計見 `docs/proposal-speed-and-web-manga.md` 第二部分。

```
擴充功能 ──Native Messaging──▶ tmw_web_host.exe ──具名管道──▶ Translation Magic Window
 （content.js 找圖、畫譯文；       （只轉送，主程式沒開時       （一張一張排進處理管線，
   background.js 抓圖、送圖）        把它叫起來）                   一律當漫畫處理）
```

## 安裝版

用安裝程式（`tools/installer/make_installer.py` 產生）裝好的主程式會一起裝 `tmw_web_host.exe` 和主機的設定檔，
並為 Chrome、Edge 註冊（目前使用者的登錄機碼，解除安裝時刪掉），不必執行下面的 `register_host.py`。
允許連線的擴充功能 ID 是從 `manifest.json` 的公鑰算出來的。

## 開發時怎麼裝

1. 建置 `tmw_web_host`（和主程式一起建置就有）。
2. 註冊主機（寫入目前使用者的 Chrome、Edge 登錄機碼；`--unregister` 移除）：
   ```
   python tools/web_extension/register_host.py
   ```
3. 瀏覽器打開 `chrome://extensions`（Edge 是 `edge://extensions`），打開「開發人員模式」，
   按「載入未封裝項目」，選這個 `extension` 資料夾。
   manifest 裡有開發用的公鑰，所以擴充功能 ID 固定是 `iohilhlbinnplmnnlipmamjenegjdggj`
   （私鑰在 `.cache/extension`，不進版本控制）。
4. 打開漫畫頁，按工具列的按鈕打開控制視窗，按「翻譯這一頁」。第一次會問要不要讓它讀取所有網站的資料
   （抓跨網域的圖片要用）。控制視窗裡可以看主程式的連線和這一頁的進度、切換原文／譯文、重試失敗的圖、
   停止並移除譯文、選辨識語言，也可以勾「這個網站自動翻譯」（之後打開這個網站就自動開始）。
5. 改了擴充功能的程式之後，在擴充功能頁按它的「重新載入」，再重新整理漫畫頁。

## 目前能做的

- 找出頁面上的漫畫圖（`<img>`、畫好而且讀得到像素的 `<canvas>`），只挑主要內容欄；連到別的網站的圖當成廣告略過
- **延遲載入的圖不等它載入**：直接讀 `data-src`、`data-original`、`srcset` 這類屬性裡的真正網址，捲到之前就翻好
- **載入整頁**：開始時（可以關掉）先把頁面自動捲到底一次再捲回來，只有捲到才給網址的網站也會把圖全部載入；
  瀏覽器內建的 `loading="lazy"` 直接改成立刻載入
- 依「現在」離畫面多近決定順序（每次送出前重排），同時交給主程式六張：主程式一頁一頁做 OCR、
  四頁同時翻譯（`core/web_pipeline_worker.h`）
- **網頁上的控制面板**：可以拖動、調透明度、縮小；看進度、切換原文／譯文、重試、載入整頁、停止。
  位置和透明度會記住；按 × 只關面板（翻譯繼續），工具列的控制視窗可以再叫出來。換頁之後面板還在
- 面板列出**失敗的原因**（例如被限流、主程式沒開、圖片抓不到），同樣的原因合在一起計數；
  可以**切換翻譯引擎**：選單是主程式「最近用過」的引擎（`core/engine_history.h`），換了之後失敗的圖自動重翻
- **不翻某張圖**：面板按「不翻某張圖…」再點網頁上的圖（例如被當成漫畫頁的橫幅、廣告），這個網站以後都略過它
  （依網址；blob 圖依內容的指紋）。清單依網站記在 `chrome.storage`，「恢復略過的圖」清空
- **翻譯擬聲字**的開關：關掉時擬聲字（對話框外、很短、多半是假名的字）的譯文馬上藏起來，
  之後的頁面不再把擬聲字送去翻譯（比較快）；再打開時，當初沒翻擬聲字的頁會重送一次
- 譯文放在緊跟著圖片的元素裡，用 CSS anchor positioning 錨定在圖片上：捲動、上面的圖載入後變高、插進新圖，
  都由瀏覽器對齊，不會落後或偏移。當不了錨點的圖（或舊瀏覽器）改用 JS 對齊，在版面變動的當下就重算
- 閱讀器把捲出畫面的圖拿掉、捲回來再建一個新元素時，譯文依圖片網址立刻蓋回去，不重新翻譯；
  網頁的程式把譯文元素拿掉時也會補回去
- `blob:`／`data:` 網址的圖（例如 MangaDex）依圖片內容（縮成 32×32 的雜湊）辨認，閱讀器換一個新的 blob 網址
  也認得；送去翻譯時拿原本的壓縮檔交給背景解碼，不在網頁的主執行緒上讀像素（以前捲動時會頓一下）。
  閱讀器捲動時把頁碼寫進網址（`/chapter/<id>/20` → `/21`）不算換章，譯文不會被拆掉
- 圖片伺服器有防盜連時，背景抓圖會帶上漫畫頁的網址當 Referer（declarativeNetRequest）；
  背景抓不到就叫網頁先載入，再從頁面讀
- 譯文的內容在 shadow DOM 裡，網頁的 CSS 碰不到；直排、描邊、背景修補的小圖、ルビ；字級跟著圖片縮放
- 同一張圖（內容相同、辨識語言相同）這次瀏覽器執行期間只翻一次；主程式另外把結果存在硬碟上
  （資料資料夾的 `web-cache`，上限 300 MB，滿了刪最久沒用的），重新整理、瀏覽器重開之後直接送回，
  不再做 OCR 和翻譯（34 頁從 210 秒變成 6 秒）。換了翻譯引擎、辨識語言、專有名詞表或程式版本就重新翻

主程式那一邊對網頁送來的整頁另外處理（`core/pipeline.h` 的 `PipelineJob::manga`、`overlayOnly`）：

- 文字偵測用整頁的大小（直的頁 768×1088、跨頁轉成橫的），不是透鏡的 960×544；另外一個偵測工作階段，
  不影響透鏡的速度
- 不丟貼著圖邊的段落（那是給透鏡切到一半的句子用的）
- 漫畫對話框偵測器框到的文字一律蓋（雲朵、爆炸形的對話框背景不是純色也照樣蓋，用背景修補）
- 原文沒有字、或只有一兩個字而且框很小的（多半是把愛心、閃光讀成了字）不蓋
- 蓋不上去的段落翻譯之前就略過（網頁沒有結果視窗，翻了也看不到）
- 主程式的記錄每頁寫「沒蓋幾段、為什麼」，查漏字時看這一行

測試：`python tools/web_extension/test_content.py`（無頭 Chrome，不必載入擴充功能、不連網）。

## 還沒做的

- 大型的擬聲字：花俏的字體 PP-OCR 多半偵測不到（網頁漫畫 34 頁裡的 114 個擬聲詞，58 個連行都沒偵測到），
  要另外找偵測方法；很小的手寫字也一樣
- 讀不到像素的 canvas（例如打亂拼圖再畫出來、而且被污染的閱讀器）改用畫面擷取
- 切成很多條的長條漫畫拼回一頁再偵測；一個對話框跨兩張圖
- 整章一起送翻譯以統一用詞
- 上架「不公開」項目
